## M2 scope — both locales together, end to end

1. **`locales/pt-pt/` and `locales/pt-br/`** — same domain files as `en-gb`
   (`core`, `culture`, and whichever domains you extract next). Translation
   unit = one domain file per job (~30 keys), with the culture's `tone` note in
   the prompt. **pt-PT and pt-BR are different cultures, not spellings** — the
   Send Translator role's rule; a Brazilian says "áudio" where a Portuguese
   user may not; let each file read native, never mechanically shared.
2. **Culture packs**: both declare **GBP** (`currency`, `symbol: "£"`,
   `usdRate: 0.79`) — Dinis's standing decision; only `intlLocale`
   (`pt-PT`/`pt-BR`), `language` and `tone` differ.
3. **The picker**: native-script names from `index.json` labels, **no flags**
   (Send's designer decision, recorded and never implemented there — implement
   it here), LIVE clickable / DRAFT visible-but-marked, choice persisted (your
   `wa-locale` key already does this).
4. **Artefact language** — the half Send never had: `options.language` rides
   the workflow declaration into the prompt templates (`{{language}}` +
   `{{tone}}` placeholders in `app/prompts/*.md`), defaulting to the UI
   locale, so the summary/infographic/chat come back in the user's language.
   The transcript stays in the language spoken.
5. **Per-locale qa-to-docs**: run the journeys per LIVE locale so each has
   pinned screenshots — that is the human review surface a locale's `live`
   bit waits for; your baseline change log records the churn.
6. **Gates**: your `check_locales.py` already grades all of this. A locale
   flips to `live` only after Dinis reviews its screenshots — until then,
   `draft` and honest.
