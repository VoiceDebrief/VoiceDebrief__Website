# Bug report for the Tools team: `addFiles` silently drops duplicate files

*Part of the [project library](https://whatsapp-voice-transcription.sgraph.ai/library/) — every doc behind this product, organised by audience.*

**from** WhatsApp Voice Note Transcribe team (embedder of the audio-transcribe engine)
**date** 2026-08-05
**severity** low-medium (confusing failure for embedders; no data loss)
**where** `en-gb/audio-transcribe/ui/state.js` `addItem` / `api/api-source.js` `addFiles`

## The behaviour

`state.addItem` dedupes on `name::sizeBytes` and returns `null` for a file already in
the queue. `addFiles` only pushes to `added` when it gets an id — so a duplicate file
comes back **neither in `added` nor in `rejected`**: `{ added: [], rejected: [] }`.

An embedder that (reasonably) treats "nothing added" as a rejection then shows the
wrong error. In our product, re-running the same voice note ("do another voice note"
with the same file, or clicking a sample twice) surfaced as *"That doesn't look like
an audio file we can read"* — misleading, and it made every repeat run fail.

## Suggested fix

Report the dedupe instead of swallowing it, e.g.
`rejected.push({ name, code: 'duplicate', id: existingId })` — returning the existing
id lets the embedder reuse the item (whose `transcribeItem` re-transcribe path already
appends versions cleanly).

## Our workaround (pipeline-side, shipped)

When `addFiles` returns nothing added and nothing rejected, we look the item up by
name+size in `getItems()` and reuse its id. Works, but every embedder has to discover
this the hard way — hence the report. Companion to our 5 Aug `.ogg` MIME report
(`v0.1.14__bug-report__ogg-mime-passthrough-causes-hallucinated-transcripts.md`).
