## How The Tasks Fit The Architecture

- **Agentic team (1)** — this repo is developed in the open by an agentic team plus
  humans, like its siblings; the team structure is the working method, so it lands first.
- **CI auto-tag (2)** — the two-branch model (`dev` → dev estate, `main` → production) is
  a core architecture decision from the 27 July arch brief; auto-tagging on both branches
  gives every push a version identity, which the version-prefixed doc convention
  (`vX.Y.Z__type__slug.md`) also depends on.
- **Static site MVP (3)** — "there is no backend, so hosting is static on GitHub Pages" is
  claim #9 of the arch brief. The MVP site is the first shipped artefact of the product
  itself, and the landing point for the domain Dinis will wire up.
- **issues-fs-lite todo (4)** — file-based issue tracking keeps the work visible inside
  the repo (open working, clause 9.2 of the contract draft) rather than in a side channel.
- **Library (5)** — the project needs its own curated knowledge base; the source docs
  currently live in two other repos, and the 27 July pack is not yet indexed by the
  Librarian anywhere.
