# sg-llm-infographic — Integration & Capabilities Guide

*Part of the [project library](https://whatsapp-voice-transcription.sgraph.ai/library/) — every doc behind this product, organised by audience.*

**Version:** v0.1.14 (component v0.1.0, code-verified 5 Aug 2026)
**Audience:** agents wiring the infographic generator into a page (this repo's M2 stage
is the reference implementation: [`website/app/infographic.js`](../../../website/app/infographic.js)).
**Source of truth:** `SGraph-AI__Tools` [`sgraph_ai_tools__static/components/llm/sg-llm-infographic/v0/v0.1/v0.1.0/`](https://github.com/the-cyber-boardroom/SGraph-AI__Tools/tree/dev/sgraph_ai_tools__static/components/llm/sg-llm-infographic/v0/v0.1/v0.1.0)
(js + css + manifest), served CORS-`*` at
`https://dev.tools.sgraph.ai/components/llm/sg-llm-infographic/v0/v0.1/v0.1.0/sg-llm-infographic.js`.
Verified by a full end-to-end run in this repo (real key, real voice note, 10.9 KB SVG).

> **One-line model:** it is a **renderer, not a caller**. The component listens for LLM
> streaming events on its **parent element**, extracts the first `<svg>…</svg>` from the
> accumulating text, and renders it live. The caller composes and sends the LLM request
> (one chat call); the component supplies the style-specific system prompt.

## 1. The shape: ONE LLM call (the M2-a open question, answered)

The 27 Jul arch brief asked "one call or two?" — **one**. The flow:

```
   caller                                       sg-llm-infographic
     | style system prompt = viz.getSystemPrompt()       |
     | user content = your prompt + the material          |
     | one streamed chat call on the shared bus cell      |
     |---- llm:request-chunk events ---------------------->  live SVG extraction,
     |                                                       progressive render
     |---- llm:request-complete --------------------------->  final SVG; emits
     |                                                       llm:infographic-ready {svg}
```

## 2. Wiring (the cell pattern, verified)

Place the component **in the same `[data-llm-bus]` cell** as an `sg-llm-request` engine
(it attaches its listeners to `parentElement`), then drive the standard `SGL_LLM` event
protocol — identical to `llm-transport`'s isolated cells but with streaming on:

```js
const cell = div('[data-llm-bus]')
cell.append(el('sg-llm-request'), el('sg-llm-infographic', { 'style-preset': 'executive' }))
mount.append(cell)                       // visible: the live render IS the progress
cell.dispatch(SGL_LLM.CONNECTED,         { provider: 'openrouter', model, apiKey })
cell.dispatch(SGL_LLM.STREAMING_CHANGED, { streaming: true })
cell.dispatch(SGL_LLM.SEND,              { messages: [system(styIePrompt), user(content)], model, provider: 'openrouter' })
// resolve on SGL_LLM.REQUEST_COMPLETE (usage/generationId via readComplete());
// the SVG via the llm:infographic-ready detail or viz.getCurrentSvg()
```

Errors are the standard typed set (`classifyLlmError`): `key-invalid` / `budget-exceeded`
/ `key-exhausted` / `rate-limited` / `llm-error`. Non-streaming also works — the
component extracts from `request-complete` — you just lose the progressive draw.

## 3. Public surface (component v0.1.0)

| Member | What |
|---|---|
| `getSystemPrompt()` | The style preset's system prompt (use it as your system message) |
| `getCurrentStyle()` / `setStyle(name)` | Style preset accessors |
| `getCurrentSvg()` | The extracted SVG string or null |
| attr `style-preset` | `executive` (default) · `technical` · `playful` · `minimal` · `bold` · `data` |
| attr `orientation` | `landscape` (1200×800, default) · `portrait` (800×1200) |
| emits `llm:infographic-ready` | `{ svg, width, height }` on parentElement |
| emits `llm:infographic-exported` | `{ format }` after its built-in Export SVG / Export PNG buttons |

Built-in UI: style selector, orientation toggle, live preview, export buttons — all in
Shadow DOM, dark-panel styling. Embedding it visible gives you all of that for free.

## 4. Guarantees and constraints (from source)

- **Sanitisation**: the extracted SVG is cleaned of `<script>` and inline event
  handlers before rendering — safe to re-embed.
- All six style prompts demand raw SVG only, `viewBox="0 0 1200 800"` (or portrait),
  no markdown fences. Models occasionally fence anyway; extraction tolerates it by
  scanning for the first `<svg>…</svg>` block.
- PNG export needs a browser context (Canvas). SVG export is a plain blob.
- Dependency: `sg-llm-events` v0.1.0+ and an `sg-llm-request` v0.1.0+ engine in the
  same cell. No other coupling — it never touches the network itself.
- Cost: one chat completion; metered like any other call on the key (our verified run:
  ~10.9 KB SVG from a 30-word transcript, within a £0.003 total pass).

## 5. NOT this component's job

Model choice (caller's; we default `google/gemini-3.5-flash`), the key (caller's, via
`CONNECTED`), the user prompt (ours is the site-served markdown
[`website/app/prompts/infographic-prompt.md`](../../../website/app/prompts/infographic-prompt.md)),
and persistence (`llm:infographic-ready` hands you the SVG — store it yourself).
