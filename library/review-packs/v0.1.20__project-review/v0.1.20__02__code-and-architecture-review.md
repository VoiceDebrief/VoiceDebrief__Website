**from** Claude (review session agent)

## 1. The Architecture As Actually Implemented

~1,600 lines of app JavaScript, event-driven, and it honestly implements the no-backend
decision. Module responsibilities are clean:

| Module | Responsibility |
|--------|----------------|
| `app.js` | Page bootstrap; the only DOM-wiring layer. Panels, chips and even tests all drive the same `window.__tool` surface — the UI is deliberately just one consumer of the API |
| `engine.js` | The Attempt-2 import harness: dynamically imports the shared engine's method-group builders from `dev.tools.sgraph.ai` and re-registers them on our own `SgToolApi('whatsapp-transcribe')`; owns the BYOK key (localStorage) and the single transport chokepoint where prompt overrides apply |
| `pipeline.js` | The one-pass state machine: normalise → ingest → transcribe → summary → optional infographic, streaming each artefact via `wa:*` events; summary/infographic failures degrade rather than abort; holds the chat's `updateMaterial`/`restoreMaterial` with originals kept |
| `audio-normalise.js` | Content sniffing by magic bytes (the issue-025 anti-hallucination fix) — never trusts the browser's MIME |
| `infographic.js` | Two render paths: image models (SSE-accumulated data-URL) and drawn SVG via the reused `sg-llm-infographic` cell |
| `chat.js` / `chat-tools.js` | M3: context rows that ARE the prompt, a fenced-block tool loop against a typed 13-tool registry, three per-exchange budgets (8 steps / 2 spend calls / $0.25) |
| `openrouter.js`, `debug-store.js`, `config.js` | Read-only OpenRouter lookups; the exchange log + prompt-override registry; origin/rate/prompt-URL config |

Components follow the immutable `wa-*/v0/v0.1/v0.1.N/` convention with versions pinned
in `app.js:12–18`. Comments cite issues and briefs throughout — code archaeology is
easy, which is rare and worth protecting.

**Strengths worth naming**: consistent typed errors mapped to user copy
(`ERROR_COPY`); `diagnoseLlmFailure` re-checking a CORS-swallowed rejection via
`GET /api/v1/key` (issue 032 — a real-world fix); the degradation policy implemented,
not just stated; masked key logging; the chat registry validating every parameter by
enum/regex and telling the model its budgets each turn.

## 2. Security Findings (the part to act on first)

**S1 — `?origin=` is a remote-code-loading vector on the live product.**
`config.js:6` lets a query parameter replace the engine origin, and `engine.js:30–41`
+ `infographic.js` then dynamically import and execute modules from it. A crafted link
(`/app/?origin=https://evil.example`) runs attacker JavaScript in the app's origin —
where the user's OpenRouter key sits in plaintext localStorage. Fix is ~5 lines: an
allowlist (`dev.tools.sgraph.ai`, `tools.sgraph.ai`, `localhost`). **Highest-priority
finding in this pack.**

**S2 — No CSP anywhere.** GitHub Pages can't set headers, but a
`<meta http-equiv="Content-Security-Policy">` carrying `script-src` and `connect-src`
would neuter S1's class entirely and bound the SVG/XSS surface.

**S3 — `set_prompt` is model-callable and persists.** The transcript is untrusted,
attacker-authorable content (anyone can forward a voice note); it flows into the chat
context; the model can call `set_prompt`, which writes a prompt override to
localStorage **across sessions**. A poisoned note could plant a permanent malicious
transcribe/summary prompt. Budgets bound spend, not persistence. `set_prompt` /
`reset_prompt` should be human-confirmed or removed from the model-callable set
(`update_transcript` is worth confirm-gating too — the "✎ edited" note is subtle).

**S4 — Model-generated SVG enters the live DOM.** innerHTML-inserted SVG won't run
`<script>` but does fire inline `on*` handlers. Sanitisation lives (or doesn't)
upstream in `sg-llm-infographic`; this repo neither sanitises nor documents the
assumption. Verify upstream or strip `on*`/`<foreignObject>` locally.

**S5 — Smaller but real**: the localStorage key is named `sg-openrouter-mgmt-key` —
"mgmt" is precisely the key class CLAUDE.md bans from clients; the name invites the
wrong paste (rename with a migration read). `app.js:245–251` interpolates a model
name into innerHTML unescaped — enum-constrained today, one refactor from not.
`setApiKey` accepts any non-empty string as "Key saved" without a `getKeyStatus`
validation ping.

## 3. Quality Smells (worth a cleanup pass, not urgent)

- **Duplication across panels**: `esc()`, the 100×100ms `tool()` poll, grip-resize,
  and elapsed-ticker logic each exist twice (chat-panel v0.1.1 vs debug-panel
  v0.1.2); two near-identical mini-markdown renderers with *different escaping
  subsets* (`wa-chat-panel.md()` vs `wa-result-card.show()`) — the escaping
  difference is also a security-relevant inconsistency. A shared versioned
  `wa-shared` util module is overdue.
- **Constants defined twice**: `CHAT_MODEL_DEFAULT` (engine.js:16, chat.js:22); the
  key-storage name (engine.js:15, wa-key-panel:5).
- `ask()` and `chat()` in engine.js are ~80% identical; one should delegate.
- **Budget accounting gap**: `used.spendUsd` counts only chat-model calls; the
  expensive spend (`run_sample`, `redraw_infographic` → transcription + image
  generation) never accrues toward the $0.25 cap — so the budget line shown to the
  model is not the truth. Thread pass costs into the meter or reword the budget.
- Two "session cost" meters (engine cost summary vs chat panel) can disagree; pick
  one source of truth.
- Dead weight: unused `TOOLS` import (chat.js:13); `website/m1-spike-test.html` still
  ships in the production deploy; no-op `ready` binding in the smoke script.
- No timeout/cancel path if a chat tool triggers a long `runPass` — `state.busy`
  blocks the user until it resolves.

## 4. Verdict

A small, unusually well-commented codebase whose implementation matches its stated
decisions — genuinely better than its age suggests. The gap is not craft but
*hardening*: S1+S2 are a real hole in a live product and cost hours to close; S3 is
the sharpest prompt-injection edge and is a policy choice more than a code change.
Close those before the seeded-key era begins, and the codebase is in honest shape for
its stage.
