## 1. The Discipline, Verified

The repo's claim to unusual documentation discipline largely **holds**, spot-checked
against the code:

- The reality doc's EXISTS rows match the files (audio-normalise, debug-panel
  versions, chat-tools, qa-deploy all present as claimed); the decision log carries
  sources.
- Done issues carry dated outcome notes with evidence; issue 025 is a model incident
  write-up — regression test, six-variant verification, two upstream bug reports.
- Provenance is real: every import in `library/README.md` names source repo and path.
- Honesty labelling is consistent (PROPOSED tags, the infographics README's "not
  current architecture documentation", disabled privacy chips in the UI).
- The peer-review loop exists in writing: the dev-pack code review found four real
  gaps, and all four are traceably resolved in dated decision-log rows.

## 2. Where The Record Has Slipped (all verified, all cheap to fix)

1. **CHANGELOG is nine tags behind its own rule.** The latest dated heading is
   v0.1.11 (31 Jul); everything since sits under "Unreleased (next tag)" although
   v0.1.12–v0.1.20 are minted. `versions.json` ends at v0.1.18 while the site serves
   v0.1.20.
2. **Reality doc contradictions**: header says updated 2026-08-03 but rows are dated
   2026-08-06; the PROPOSED section still says the M3 chat's live run and dev merge
   "do not exist yet" while the EXISTS row above says "validated live by Dinis" and
   git shows 034/035 merged.
3. **`issues/done/README.md`** header says 29 Jul while listing issues through 035.
4. **Dev packs not closed out**: both the v0.1.1 pack and the v0.1.18 chat design
   brief still say "PROPOSED — does not exist yet" about shipped work.
5. **Two GitHub org names** (`sgraph-ai` vs `the-cyber-boardroom`) in cross-repo
   links, with no note saying which owns what.
6. **CC BY footer rule partially observed**: the brief pack (all seven files), most
   ROLE files, `team/README.md` and `CHANGELOG.md` lack the footer CLAUDE.md mandates.

## 3. The Licence Contradiction (highest consequence-to-effort)

`LICENSE` is the full Apache 2.0 text, while README, CLAUDE.md, the tech-stack guide
and the commercial-model doc all say the code licence is "MIT or Apache 2.0 — final
choice pending". The 28 Jul completion report flagged the LICENSE as scaffold
residue; ten days on, an outside reader cannot tell whether the repo is
Apache-2.0-licensed or unlicensed-pending-decision. For a project whose strategy is
"openness shrinks the legal surface", this is the one legal artefact that is
genuinely unclear. One decision, one commit — and it closes a contract-draft open
point too.

## 4. Gaps A New Reader Hits

- **No architecture-as-built doc.** Brief-pack 02 is the "canonical architecture" but
  predates everything actually built (Attempt-2 engine cut, the `whatsapp-transcribe`
  action surface, chat registry, two estates, cache-busting). Today the real
  architecture is reconstructable only from reality doc + spike note + changelog
  prose. The app's own API surface (27+ actions, 13 chat tools) has no reference —
  ironic, given the excellent capability guides maintained for the *upstream* tools.
- **No CONTRIBUTING.md / SECURITY.md** — GitHub-native visitors expect both;
  SECURITY.md with a disclosure contact matters extra for a product planning a
  deliberately seeded key.
- **No runbooks**: key rotation/revocation, QA-deploy failure, Netlify secrets,
  rollback, OpenRouter outage — happy path only. No incident-response note either,
  despite issue 025 having *been* a well-handled incident worth formalising.
- **Role folders are mostly empty.** Only the Librarian has ever filed a review.
  AppSec, DPO, QA, Architect have zero role output despite issues explicitly waiting
  on them — most notably the **AppSec seeded-key conditions doc** (issue 010:
  required "before any key ships") and the **privacy notice** (DPO ROLE: "ships with
  the MVP, not after it" — the MVP shipped 5 Aug; the live site promises the notice
  "with the beta"). The team structure is documented far better than exercised.
