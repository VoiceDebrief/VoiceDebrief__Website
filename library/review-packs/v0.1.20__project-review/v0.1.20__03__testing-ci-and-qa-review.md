## 1. What The Gate Really Catches (and it's a lot)

Four layers, honestly described in `tests/README.md`, and CI genuinely gates the tag
on them (`increment-tag` `needs: [test]`):

- **Unit (22, node --test, no mocks of our own modules)** — `audio-normalise` tested
  against *real fixture bytes* including the full issue-025 lying-MIME matrix;
  `chat-tools` parser edge cases; `debug-store` override semantics with non-mutation
  assertions.
- **Integration (Playwright, real Chromium, real engine origin)** — `app-boot`
  verifies boot, the full manifest action contract, real-fixture ingest, prompt
  override round-trips, zero page errors. `chat-loop` is the standout: a scripted
  OpenRouter mock drives a keyless full pass, a prose answer, a real tool call that
  lands an SVG, and the update/restore-material flow with audit-log counts.
- **Post-deploy live QA (16 checks)** — CDN-propagation wait, every `?v=`-stamped
  asset resolves (the issue-026 class), samples/prompts/manifest reachable, CORS.
- **Keyed e2e** — deliberately in-session only, for cost. Reasonable.

For a nine-day-old repo this is an unusually good estate. The claims below are about
what it *misses*.

## 2. Coverage Gaps, In Priority Order

1. **The default production path has zero tests.** The *image* infographic (the
   default since issue 031) is never exercised — only the SVG path via the chat-loop
   mock. Extend the mock's SSE to emit image deltas.
2. **The escape/render code has zero tests.** `wa-result-card.show()` and
   `wa-chat-panel.md()` are the XSS-relevant code (see doc 02 S4) and no test feeds
   them hostile strings. A hostile-transcript case in the chat-loop mock
   (`<img onerror=…>`) is the test that guards the whole render surface.
3. **Budgets are never driven to their limits.** Nothing exercises the 8-step /
   2-spend-call / $0.25 stops; such a test would also have caught the spendUsd
   accounting gap (doc 02 §3).
4. **No failure injection.** 401/402/429 from the mock → `ERROR_COPY` mapping and
   `diagnoseLlmFailure` are unverified — the app's error UX is untested.
5. **Untested modules**: `openrouter.js` (the 404-only retry branch is subtle),
   `pipeline.js` error paths (dedupe recovery, cancel), `app.js` entirely.
6. **QA misses `chat-prompt.md`** in its prompt-reachability list — a deploy that
   drops it silently degrades chat to the hardcoded fallback. One-line fix.
7. **Format matrix outruns the fixtures**: QA's ROLE calls the format matrix "test
   surface #1", but `tests/fixtures/` has only `.opus`/`.ogg` — no `.m4a`/iPhone leg.
8. **Session-artefact scripts checked in as tests**: `tests/playwright/app-smoke.mjs`
   and `ogg-variant-matrix.mjs` carry hardcoded `/home/user/...` paths and reference
   a `serve-cors.py` that isn't in the repo — they can't run anywhere else. Move or
   generalise.

## 3. Pipeline Assessment

**Good**: staged and honest (test → tag → stamp+cache-bust → deploy → live QA); the
cache-buster closes a real observed failure and the QA step verifies every stamped
URL; the qa/Netlify estate computes `next-version-qa.<sha>` from tags, respecting
"CI owns `version`"; sensible per-job permissions.

**Fragile / missing**:

1. **No secret scanning, no pre-commit control** — the exact gap issue 013 and the
   28 Jul brief name ("documentation alone will not hold"). With a deliberately
   seeded key coming, gitleaks in CI + a pre-commit hook is the top pipeline add.
2. **No lint/format/type pass at all** — cheapest defect net not deployed; ESLint in
   the test job is an afternoon.
3. **Supply chain**: `owasp-sbot/OSBot-GitHub-Actions@dev` pins a mutable branch of a
   third-party action that runs with `contents: write` — pin to a SHA. Playwright is
   installed unpinned (`playwright@1`, no lockfile).
4. **Checkout-then-`git pull` race** in build/deploy jobs: if anything lands on `dev`
   between tag and pull, the deployed content isn't the tagged commit. Check out the
   bump SHA exactly.
5. **The integration gate depends on live `dev.tools.sgraph.ai`** — an upstream
   outage blocks all releases, and nothing pins which engine version a release was
   tested against. Use the existing MIRROR_DIR mechanism for the gate; keep one
   live-origin job as a non-blocking canary.
6. **`main` is a dead end**: pushes run tests and mint a *major* tag, but no deploy
   job exists for `main` — the production domain serves dev builds. Wire it or
   suspend major-tagging until it's real (decision for Dinis; see doc 07).
7. Minor: `pyproject.toml` duplicates the version (silent-drift risk); fixed ports
   and `sleep 1200` in integration setup (flake risk); a deployed-but-unverified
   release has no rollback step if live QA fails.
8. **No scheduled keyed canary**: a weekly spend-capped real-model run would catch
   the regression classes mocks cannot (hallucination behaviour, image-model output
   shape changes).

## 4. Verdict

The testing story is the strongest NFR in the project and — per doc 06 — deserves to
be told publicly. The honest caveats: the default path and the escape code are the
two untested surfaces that matter most, and the pipeline's missing basics (secret
scan, lint, SHA-pinning) are all cheap relative to what's already built.
