# What `?origin=` does

*Part of the [project library](https://whatsapp-voice-transcription.sgraph.ai/library/) — every doc behind this product, organised by audience.*

**status** EXISTS. The parameter has been there since M1; the allow-list described in
§4 was added 6 Aug 2026 (issue 038).
**audience** anyone working on the app, and anyone reviewing its security.

---

## 1. The one-sentence answer

`?origin=` tells the app **which server to load the transcription engine from** —
because this product does not contain an engine, it borrows one at runtime.

## 2. Why the app needs an origin at all

The whole product is a browser page with no backend. It does not ship the audio
pipeline: it *imports* the proven `audio-transcribe` engine from the SGraph tools site
over the network, live, as ES modules ([the spike verdict, dev pack brief
06](../dev_packs/v0.1.1__audio-transcribe-integration/03__dev__implementation-brief.md)):

```js
// website/app/engine.js
import(`${ORIGIN}/en-gb/audio-transcribe/api/api-transcribe.js`)
import(`${ORIGIN}/core/sg-tool-api/v0/v0.1/v0.1.0/sg-tool-api.js`)
// …ten modules in total
```

`ORIGIN` comes from `website/app/config.js`. Its default is
`https://dev.tools.sgraph.ai`. That default is why the app works with no query string
at all — and why the QA live check verifies that host is up and sends
`access-control-allow-origin: *`. If the tools site is unreachable, our app cannot boot,
which is a deliberate trade (reuse over rewrite) and the reason boot failure has its own
error message.

## 3. What the parameter is for

Two jobs, both development:

1. **Running the app against a local copy of the engine.** In a sandbox with no network
   route to the tools site, the tests serve a mirror on localhost and start the app with
   `?origin=http://127.0.0.1:8124`. Same product code, local engine.
2. **Trying a different engine build** — for example pointing at production
   `tools.sgraph.ai` instead of `dev.` — without editing, rebuilding or deploying
   anything.

It is not a user-facing feature. Nothing in the UI sets it, and nothing links to it.

## 4. Why it is restricted (and was not, until 6 Aug 2026)

Read what the parameter actually controls: **the URL that JavaScript is imported and
executed from, inside our page.** That code runs with everything the page has —
including the user's OpenRouter API key, which lives in
`localStorage['sg-openrouter-mgmt-key']`.

Before the allow-list, this link was enough:

```
https://whatsapp-voice-transcription.sgraph.ai/app/?origin=https://somewhere-else
```

The domain is ours and looks entirely trustworthy; the page loads normally; and every
engine module comes from someone else's server. That code could read the key out of
localStorage and post it anywhere. There is no CSP on the site to catch it, and the
attacker's own server can send whatever CORS headers it likes, so nothing else stood in
the way. In short: a credential-theft vector wearing a legitimate URL.

**The fix** (`config.js`, `resolveOrigin()`): the value must match the allow-list —

| Allowed | Why |
|---|---|
| `https://dev.tools.sgraph.ai`, `https://tools.sgraph.ai` | the real engine, dev and production |
| `http(s)://localhost[:port]`, `http(s)://127.0.0.1[:port]` | local development and the test mirror |

Anything else is **ignored**: the app falls back to the default and logs a warning
(loudly, because a blocked override means the page is not running what the link asked
for — and it might be someone else's attempt rather than a typo). The regexes are
anchored end-to-end, so `https://dev.tools.sgraph.ai.evil.example`,
`https://evil.example/dev.tools.sgraph.ai`, `https://dev-tools.sgraph.ai` and a plain
`http://` downgrade all fail. Those cases are in `tests/unit/config.test.mjs`.

## 5. How to use it

```bash
# the default — nothing to pass
https://whatsapp-voice-transcription.sgraph.ai/app/

# against a local mirror of the engine (what the integration tests do)
http://127.0.0.1:8123/app/?origin=http://127.0.0.1:8124

# against the production engine build
https://whatsapp-voice-transcription.sgraph.ai/app/?origin=https://tools.sgraph.ai
```

To confirm which engine a page is actually running, open the ⚙ debug pane: every LLM
call shows its model and its full request, and the browser's network tab shows where the
modules were fetched from. A rejected override shows as a console warning.

## 6. If you need to add an origin

Add a regex to `ALLOWED_ORIGINS` in `website/app/config.js` and a case to
`tests/unit/config.test.mjs`. Anchor it (`^…$`) and require `https` for anything that is
not localhost. Treat the list as a security control, not configuration: everything on it
can execute code in the page, beside a user's API key.
